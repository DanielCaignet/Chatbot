# ADR-003 — Un stack por cliente en una sola VM Always Free

> Inmutable. Si la decision cambia se escribe un ADR nuevo con `supersedes: [ADR-003]`.

## Contexto
El usuario quiere todo gratis y cobrar solo al cliente, con una sola Oracle VM Always Free ARM A1. Los docs actuales dicen que Always Free A1 equivale a 2 OCPU / 12 GB [EXT:Oracle Always Free].

## Decision
Un `docker compose -p <cliente>` por [[Tenant]] (Hermes + SAS + Postgres propio si aplica). Compartidos: Traefik, Evolution API (instancia por número) y el gateway-cola particionado por cliente, para ahorrar RAM.

## Alternativas descartadas
- Multi-tenant en una sola instancia — descartado: un fallo o una fuga cruza clientes.
- Una VM por cliente — descartado: el free tier da una sola.

## Consecuencias
- El cupo de clientes por VM se mide en el spike (RAM por stack).
- Riesgo de reclamo por inactividad bajo: exige CPU, red y memoria bajo 20 % a la vez.
- Una sola VM es punto único de falla: backups diarios fuera de la VM.
