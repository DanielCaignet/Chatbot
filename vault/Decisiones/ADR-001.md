# ADR-001 — Canal WhatsApp con Evolution API sobre Baileys

> Inmutable. Si la decision cambia se escribe un ADR nuevo con `supersedes: [ADR-001]`.

## Contexto
El usuario eligió Baileys (no oficial) para WhatsApp de clientes, aceptando el riesgo de ban. Hace falta además una ruta a la API oficial y soporte multi-número.

## Decision
Usar **Evolution API** (motor Baileys) como capa de canal, detrás de la interfaz [[Canal]]. Una instancia por número de cliente. Se cumple su condición de licencia: aviso visible de que se usa Evolution API en la documentación o configuración del admin [EXT:Evolution API].

## Alternativas descartadas
- Escribir un gateway Baileys propio — descartado: Evolution ya lo resuelve y agrega Cloud API en la misma pieza.
- Bridge WhatsApp de Hermes — descartado: no respeta el proxy (D-018/D-019 de Agent Factory) y no permite el takeover propio.
- WAHA / BuilderBot — quedan como alternativas si Evolution no rinde en el spike.

## Consecuencias
- Migrar a Cloud API = cambiar configuración, no código.
- Dependencia de un tercero con licencia Apache-2.0 con condiciones.
- Fijar versión de Baileys/Evolution: existió un fork malicioso en npm [EXT:Ban de WhatsApp en bots 2026].
